# Draken Portfolio

> Personal developer portfolio for showcasing software projects, technical skills, and engineering work.

## Overview

This is my personal developer portfolio.

The goal is not to reproduce a traditional résumé website. The portfolio is designed to demonstrate how I think, what I build, and the technical problems I can solve.

The site will focus primarily on selected projects, with supporting information about my background, technical capabilities, and experience.

## Goals

* Present my strongest software projects clearly.
* Demonstrate practical engineering ability rather than simply listing technologies.
* Make important projects easy to explore.
* Show technical decisions, architecture, and implementation details where relevant.
* Create a distinctive visual identity without sacrificing usability.
* Keep the website fast, responsive, accessible, and maintainable.
* Use the project itself as an opportunity to properly learn and understand the technologies used.

## Target Audience

The primary audience is:

* Recruiters
* Software engineers
* Engineering managers
* Potential clients or collaborators

A visitor should understand what I build and what I am capable of within approximately one minute.

## Design Philosophy

The portfolio should feel like a developer's workspace rather than a résumé converted into a webpage.

Visual direction:

* Dark
* Technical
* Minimal
* Futuristic
* Professional
* Strong typography
* Controlled animation
* High visual hierarchy

The interface should communicate technical competence without becoming visually noisy.

## Development Principles

### 1. Understand before implementing

I should understand the code I add to the project.

AI can be used as a learning and debugging tool, but generated code should not be blindly copied into the project.

### 2. Build reusable components

Repeated UI patterns should become reusable React components rather than duplicated markup.

### 3. Keep the architecture simple

Do not introduce a backend, database, CMS, authentication system, or other infrastructure unless the portfolio actually needs it.

### 4. Performance matters

Animations and visual effects should not come at the cost of poor loading performance or usability.

### 5. Accessibility matters

The portfolio should remain usable with:

* Keyboard navigation
* Screen readers
* Reduced-motion preferences
* Mobile devices
* Different screen sizes
